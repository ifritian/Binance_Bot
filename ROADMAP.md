# Roadmap

Живой список доработок бота, ориентированных на профит и охват (не
мелкие баги - для них есть просто git-история и комментарии в коде типа
"P1.1", "A2" и т.п. из более раннего, несохранённого в файле роадмапа).
Заведён, чтобы не полагаться на память чата - при обсуждении новых
доработок пункты сразу дописываются сюда, статус обновляется по ходу
работы.

Статусы: `предложено` -> `в работе` -> `сделано` (дата) / `отклонено`
(с причиной, не удаляем - чтобы не предлагать то же самое повторно).

## Предложено, ждёт решения

### P1. Разделить форматы по площадкам (Square / Telegram / Bluesky)
**Статус: предложено** (решение пользователя 2026-11-03: пока дублируем видео везде, потом разделяем)

Сейчас новые форматы почти без изменений дублируются во все три площадки (`CROSSPOST_FORMATS`, видео - `_crosspost_video`).
У площадок разная аудитория и механика, поэтому форматы стоит разводить:

- **Binance Square** (комиссия Write-to-Earn, виджет цены по $тикерам): оставляем всё, что заканчивается кликабельным $тикером
  (Market Shock, Breaking, Level Check, hot mover). Без ссылок. Дневное окно и суточный потолок.
- **Telegram** (подписчики, цель 500 для Binance Affiliate): форматы для удержания и обсуждения: опросы и итоги, бот-команды,
  Receipts демо-фьючерсов, длинные новостные видео, анонсы. Ссылки разрешены. Без потолка и без дневного окна.
- **Bluesky** (англоязычная лента, ссылки и обсуждение): Wry (юмор), новости со ссылкой на источник, короткие видео,
  Receipts. Лимит 300 символов и отдельный тон. Ссылки разрешены.
- Для каждого формата завести таблицу `PLATFORM_FORMATS = {формат: {square, telegram, bluesky, свой текст/подпись}}` вместо одного
  общего `CROSSPOST_FORMATS`; для видео - свои подписи, длительности и нарезки (например, 15-секундная версия для Square,
  полная для Telegram).
- Метрики: просмотры Square считаем вручную по скриншотам Creator Center; для Telegram - просмотры постов и число подписчиков
  (`audience_log`), для Bluesky - лайки/репосты через API. Решения по разделению принимать по этим данным, а не по ощущениям.
- Эмодзи-акценты и шутки Wry сейчас общие для всех площадок: на Telegram/Bluesky можно чаще, на Square - как сейчас.

### R2. Score слабо предсказывает исход сделки в среднем по всем стратегиям
**Статус: предложено**

По снимку статистики: "Conservative" (score>=90) win-rate 36.7%, но
средний результат хуже, чем у "Aggressive" (score<70): +0.18% против
+0.28%. Разница по win-rate между tier'ами тоже небольшая (28.3-36.7%).
Нужно периодически сверять score-формулы (RSI+Bollinger, MACD,
Donchian, HTF confluence) с фактическими исходами - возможно,
компоненты score стоит перевзвесить или часть из них слабо
информативна. Решение по конкретным изменениям - после того, как R1
даст эффект и накопится чистая статистика без искажения от текущего
дисбаланса Donchian.

### R3. Нет обратной связи по реальным просмотрам/охвату постов
**Статус: предложено**

`binance_publisher.py` умеет только публиковать - нет метода читать
статистику (просмотры/лайки/репосты) уже опубликованного. Вся работа
над анти-каннибализацией (см. `main._square_slot_available`,
`config.MIN_SQUARE_POST_SPACING_MINUTES`) и разнообразием тикеров -
применение общих принципов без проверки на реальных цифрах Binance
Square. Нужно узнать, отдаёт ли API Binance Square статистику по своим
постам (creator-эндпоинты), и если да - подключить, чтобы замкнуть
цикл "что публикуем -> что реально работает" и дальше принимать
решения по формату/времени/тикерам на основе данных, а не теории.

## Сделано

### R1. Donchian Breakout душит статистику публикаций
**Статус: сделано** (эта сессия)

Стратегия давала ~82% всех сигналов (488 из ~594 по снимку статистики)
при худшем среднем результате среди стратегий с приличной выборкой.
Автокоррекция (`strategy_tuner.py`) существовала, но структурно была
слишком слаба: HTF-подтверждение (`multi_timeframe.py`) может добавить
к score до +24 (3 ТФ * `CONFLUENCE_BONUS_PER_TF`=8), а старый потолок
штрафа (`MAX_PENALTY`) был всего 15, и старая формула `deficit/2` на
реальном (не катастрофическом) win-rate Donchian (~21-30%) давала
штраф всего +5..+9 - даже близко не доходя до собственного потолка.

Правка: формула штрафа стала линейной (без /2), потолок поднят с 15 до
25 (больше максимального HTF-буста +24, но оставляет 5-очковый зазор
до 100 - автоматика по-прежнему не может заблокировать стратегию
полностью, тот же принцип, что был заложен изначально). См.
`strategy_tuner.py`, `test_strategy_tuner.py`. Автоматически
подхватывается в `accuracy_report_generator.py` (уже был подключён к
`describe_active_adjustments()`) - публичный отчёт о точности сам
покажет новые, более чувствительные штрафы.

Дальше по этому пункту - смотреть на реальную статистику после
деплоя: снизилась ли доля Donchian Breakout в объёме публикаций и как
изменился общий win-rate за следующие 2-4 недели (`TUNING_LOOKBACK_DAYS`
= 30д - на меньшем окне рано подводить итог).
